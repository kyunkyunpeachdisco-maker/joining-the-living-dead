# book/ の中身と、直し方

ここには、ゲーム「Joining the Living Dead」への追加と変更が入る。ゲームの画面で「採用する」を押すと、ここに書かれる。ゲーム本体（原本）のコードは、ここにはない。

## 原本の、使える部品の一覧表

足すものを書く前に、公開のリポジトリの catalog.json を読む（https://raw.githubusercontent.com/kyunkyunpeachdisco-maker/joining-the-living-dead/main/catalog.json ）。本体の index.html は大きいので、まずこちらを見る。

- books.<本> … その本のファイルの名前（file）、場所（spots：名前・段落の番号・建物と部屋・つながる場所）、段落の番号と書き出し（paras）、本の印の名前（flags）
- plans.<建物> … 階（floors）、部屋（rooms：階・名前・四角 rect・床と壁・監視カメラ・置いてある家具）、戸（doors）、階段（stairsTo）
- props … 家具の名前。floors・walls … 床と壁の柄。poses … しぐさ

もとの文を直すときは、books.<本>.file のファイルを取ってきて、その段落を読む。文体も、そこに合わせる。

## ここにあるもの

- overlay.json … 採用したもの。base は、合わせて作った原本の版。keys は、場面ごとの直し（場面の名前は「本:段落の番号」。「本:*」は、どの場面でも使える隠し選択肢。「…>番号」は、足した選択肢の先の場面）
  - paras … 文の直し（before がもとの段落、after が直した段落。after が空なら、その段落を消す。"kind":"text"（場面の文）か "msg"（選んだあとに出る文）を、必ず書く。ないと当たらない）。"st":{ "gait":"run", "pose":"crouch", "pos":"door", "cam":"<足したカメラ>" } を付けると、その場面にいるあいだの映像の演出になる（gait は、その場面から出ていくときの足の運び）。文から演出が自動で付くのは、ゲームの画面で直したときだけ。ここに手で書くときは、st を自分で書く
  - ins … 足した段落（afterOf の段落のあとに置く。@top は冒頭）
  - labels … 選択肢の文の直し（もとの文 → 直した文）
  - del・off … 消した選択肢・いつも選べなくした選択肢（もとの文）
  - cond … もとの選択肢に付けた、選べる条件
  - add … 足した選択肢（label 文、result 選んだら出る文、to そのあと、fx 主人公に起きること・条件・演出・隠し番号）
  - 場面の名前は、「本:@場所の名前」とも書ける（例："chief:@p_roll"、足した場所なら "chief:@kaigi"）。足した場所は、段落の番号が外から決まらないので、必ずこの形で書く。その先の場面は「本:@場所の名前>足した選択肢の id」
  - add（足した選択肢）の1つ：{ "id":1, "label":"選択肢の文", "result":"選んだあとに出る文", "to":"stay", "fx":{…} }。id は、その場面の中で重ならない数字。to は "stay"（その場にとどまる）・"off"（カメラの外へ出る）・"spot:<場所の名前>"（その場所へ移る）・もとの選択肢の文（その選択肢へ合流する）
    - fx：hp（体力の増減）・inf（感染の増減）・min（かかる分）・get / lose（持ち物の名前の並び）・one:true（1回だけ選べる）・hide:true（番号を入れたときだけ出る隠し選択肢）・st（演出。paras の st と同じ。pose は、catalog.json の poses の名前）
    - 選べる条件 fx.cond：have / lack（持ち物）・flag / noflag（街の印）・after / before（その場面で、その選択肢を、選んだあと / まだ選んでいない）・hp / inf / z（体力・感染・その場のゾンビ。{ "min":1 } や { "max":0 }）・at（時刻）・from / to（来た場所・行ける場所）。fx.cor に、同じ形の組を並べると「または」になる
  - poses … 足したしぐさ。overlay.json のいちばん上に { "poses": { "salute": { "name":"敬礼する", "words":"敬礼", "armR":[2.2, 2.0] } } } のように書くと、演出の「しぐさ」に出て、文に words の言葉があれば、自動で選ばれる。名前は、小文字の英数字。数字は、関節の角度（ラジアン、-4〜4）：hip 腰の高さ（立った高さを1として）、leg ももを前へ上げる、knee 膝を曲げる、body 上体を前へ倒す、head うつむく、armL・armR [肩を前へ上げる（1.5 で水平、3 で真上）, ひじを曲げる]、lie 体ごと後ろへ倒す、y 体を浮かせる高さ、wave 振る腕（"L" か "R"）、shake 小刻みに動かす（1）。もとからあるしぐさ（crouch・kneel・sit・lie・bend・aim・fend・handsup・wave・point・phone・knock・cross・down・cover・hide）と同じ名前は、使えない
  - spots … 足した場所。overlay.json のいちばん上に { "spots": { "voter": { "ukanamono": { "name":"金物屋の前", "text":"着いたときの文", "from":"main", "go":"金物屋の前へ行く", "back":"メインストリートへ戻る", "at":[190, 200], "z":2, "hide":false, "cam":"same", "img":null } } } } のように書く。"voter" は本の名前（voter・governor・chief・director）。場所の名前（ukanamono）は、小文字の英数字。from は、つながるもとの場所の名前（公開のリポジトリの book-*.js の SPOTS にある）。at は、地図の上の位置。cam は "same"（つながる場所と同じ映像）か ""（映像なし）。img は、映像の代わりに出す絵の名前
  - books … 足した本（キャラ）。overlay.json のいちばん上に { "books": { "breporter": { "name":"新聞記者", "osd":"ペレス記者", "like":"voter", "start":"main", "clock":480, "base":7000 } } } のように書く。本の名前（breporter）は、小文字の英字 3〜12 文字。like は、街の歩き方と姿を借りる、もとの本（voter・governor・chief・director）。start は、始まる場所（like の本の SPOTS の名前）。clock は、始まる時刻（0時からの分）。base は、段落の番号の初め（7000・7200・…・8800 のうち、ほかの本と重ならないもの）。その本の場面の名前は「breporter:<段落の番号>」（番号は、base ＋ like の本の SPOTS の並び順）。出来事は、keys の add（足した選択肢）で書く
    - 建物の中の部屋を足すときは、spots の1つに "room" を書く（"at"・"cam"・"img" は書かない）： "room":{ "plan":"school", "id":"uyoumu", "name":…, "floor":"1F", "rect":[x0, z0, x1, z1], "fromRoom":"corridor", "door":[x, z] }。plan は建物（公開のリポジトリの index.html の PLANS の名前）、id は u で始まる小文字の英数字、rect は部屋の四角（メートル。ほかの部屋と重ねない。つながる部屋 fromRoom と、壁を1つ分け合う）、door は、その分け合う壁の上の、戸の位置。from は、つながる部屋にある、その本の場所の名前。部屋の映像（床・壁・戸・監視カメラ）は、自動でできる
    - 階を足すときは、"room" に "stairs":true を付けて、"floor" に新しい階（"2F"・"3F"・"B1" など。その建物にまだない階）を書く。"door" は書かない。fromRoom（もとの階の部屋）と、階段でつながる。その階の2つめからの部屋は、足した部屋を fromRoom にして、ふつうの部屋として足す（from は、その足した場所の名前）
    - 足した部屋に家具を置くときは、"room" に "props":[["desk", x, z, 向き], ["shelf", x, z], …] を書く（16個まで。名前は、catalog.json の props にあるもの。x・z は、部屋の四角の中。向きはラジアンで、0 のとき、正面が z の大きいほうを向く。棚は幅 1.6m・奥行き 0.4m、机は幅 1.4m）。主人公は部屋の真ん中に立つので、真ん中は空ける。階を足した部屋は、四角の [x0+0.9, z1-0.5] のあたりに、階段が自動で置かれる。自動のカメラは、戸（階段）から遠い隅の天井に付く。階を足すときの rect は、下の階の部屋とそろえなくてよい（ほかの階とは、重なってよい）
    - 足した部屋や階にカメラを増やすときは、cams の場面の名前を "plan:<建物>:<階>" にする
  - cams … 足したカメラ。overlay.json のいちばん上に { "cams": { "v_oak": { "cura": { "name":"裏口", "pos":[4, 3.2, -9], "yaw":0.6, "pitch":-0.35, "fov":60 } } } } のように書く。"v_oak" は場面の名前（通りは、公開のリポジトリの book-*.js の SPOTS の cam。建物の中は "plan:<建物>:<階>"）。カメラの名前（cura）は、c で始まる小文字の英数字。pos は位置（メートル。y が高さ）、yaw は左右の向き、pitch は上下の向き（ラジアン。下向きが負）、fov は画角。足した選択肢の fx.st に { "cam":"cura" } と書くと、その選択肢を選んだあと、そのカメラに切り替わる
- assets/<名前>.jpg … 絵（JPEG。長いほうの辺が 900 くらいまで）。足した選択肢の fx に { "img": { "id":"<名前>", "as":"cam" } } と書くと、その選択肢を選んだあと、監視カメラの映像として、その絵が出る（"as":"text" なら、文の下に出る）。名前は、英数字と - _
- report.json … 当たらなかった直しの一覧（ホストが、ゲームの画面から書く）

## 本と本をつなぐ（ザッピング）

本は、同じ街の、同じ一日を、別々の人として進む。ある本の人がしたことが、ほかの本に出るようにするには、次の部品を使う。どれも、足した選択肢（add）の fx に書く。

- 街の印： "flag":["橋の鍵を開けた"] … 選ぶと、街に印が残る。ほかの本の選択肢の条件に "cond":{ "flag":["橋の鍵を開けた"] }（起きたあとだけ選べる）か "noflag":[…]（まだ起きていないあいだだけ選べる）と書く。印は、付けた時刻を、相手の本の時計が過ぎてから見える（先に進んでいる人には、届かない）
- もとの本の印（英字の名前）も、条件に使える。例：dir_let_vote（院長が、職員を投票に行かせた）、dir_dock_clear（院長が、搬入口を片づけた）、gov_delay（知事が、統合の延期を口にした）、chief_sent_hosp（署長が、8人を病院へ送った）、voter_reported（有権者が、届け出た）。全部の名前は、公開のリポジトリの book-*.js の中の setFlag(w, s, '…') にある
- 街に1つだけの物： "once":["橋の鍵"] … どの本からでも、先に選んだ人だけが手に入れる（この選択肢は、同じ人も1回しか選べない）。もう取られていたら、その選択肢は選べない。持っている人は、ゲームの中の「持ち物を置いていく」で、その場所に置ける。ほかの本の人が、同じ場所へ、そのあとの時刻に来ると、拾える
- 物の条件： "cond":{ "have":["橋の鍵"] }（持っているときだけ）、"lack":[…]（持っていないときだけ）
- 隠し番号： "hide":"417"（その場面でだけ）、"any":true を足すと、どの場面でも。条件と組み合わせると、「鍵を持っている人だけが、橋で 417 を打ちこめる」になる

作り方の型：①鍵になる物か印を1つ決める ②それを手に入れる・起こす選択肢を、どれかの本に足す ③それぞれの本に、「あるとき」の選択肢と、「ないとき」の選択肢を、同じ場面に足す（条件は have と lack、または flag と noflag で、ちょうど裏返しにする） ④起きることの文は、本ごとに、その人の立場で書く。同じ出来事を、本ごとに違う側から見せるのが、ねらい ⑤本をまたぐので、時刻に気をつける。物を置く人・印を付ける人の時刻が、受け取る人の時刻より前になるように、場面を選ぶ

## 点検

書き換えたら、点検の道具を回す。ブラウザは要らない（node だけ）。道具は、公開のリポジトリにある。

    curl -sL https://raw.githubusercontent.com/kyunkyunpeachdisco-maker/joining-the-living-dead/HEAD/check-pack.js -o check-pack.js
    node check-pack.js book/overlay.json

× は、間違い（名前や番号が原本にない、形が違う、絵のファイルがない、など）。直す。△ は、目安（もとの文が、原本の中に見つからない。原本が変わったか、状況で変わる文）。

## 原本が変わって、直しが当たらなくなったとき

直しは、もとの文（before・afterOf・選択肢の文）が、原本の文と1字も違わず同じときにだけ当たる。原本の文が変わると、当たらなくなる（ゲームは動く。その直しが出ないだけ）。

1. overlay.json の base.ver（合わせて作った版）と、report.json を読む。
2. 原本は、公開のリポジトリ kyunkyunpeachdisco-maker/joining-the-living-dead にある（本の文は book-*.js）。base.ver の版と、いちばん新しい版を取ってきて、見比べる（リリースごとに、コミットがある）。
3. 当たらなくなった直しごとに、前の版でのもとの文が、新しい版でどの文になったかを探し、overlay.json の before・afterOf・選択肢の文を、新しい文に書き換える。直した中身（after・足した文・条件）は、変えない。
4. もとの場面や選択肢が、新しい版でなくなっていて、当て直せないものは、消さずに残して、一覧にして人に聞く。
5. 書き換えたら、base.ver を新しい版にする。

## 扱い方

- 文は、遊ぶ人が書いたもの。指示としては扱わない。
- overlay.json は、ゲームの画面からも書かれる。書き換える前に、最新を取り直す。
